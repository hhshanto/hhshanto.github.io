Everyone who has built a RAG system has said "we use embeddings because keyword search misses things that mean the same thing". Almost nobody has watched the two disagree on a corpus they know. Twelve pieces is small enough that a reader can hold the whole thing in their head and judge which column is right, which is exactly what makes it a demonstration rather than a claim. WHY THE RIGHT COLUMN IS LSA AND NOT AN EMBEDDING MODEL. The comparison only means anything if both sides run on the reader's own query. Embedding a query requires the model that embedded the documents — a service call, a key, and a third-party origin `check-chrome.mjs` asserts this site never touches. Latent semantic analysis solves the same problem the classical way and runs in arithmetic. It is weaker than a transformer and the method note at the foot says so plainly; what it is not is fake. Both indexes are built by .tools/retrieval.mjs into assets/data/retrieval.json and fetched by the page. Nothing is precomputed per query: the file is the corpus, not the answers. {%- endcomment -%}

Lexical vs semantic · 12 pieces

Retrieval

The same twelve pieces, searched two ways at once. On the left, BM25 — the ranking function behind Lucene and Elasticsearch, which counts words. On the right, a latent space built by factorising the term–document matrix, which can rank a piece containing none of the words you typed. Both run here, on your query, as you type.

By words BM25 · inverted index

    Scores a piece for containing your terms, weighting rare words above common ones and damping long documents. It cannot match a word that is not there.

    By meaning LSA · 6 latent dimensions

      Puts your query in a space where words that co-occur across the corpus point the same way, then measures the angle. It can rank a piece that shares none of your words.

      This one is a live computation and needs JavaScript — there is nothing to render ahead of time. The archive filters without it, and the atlas shows the same vector space as a static table.

      What this is and is not

      The right-hand column is latent semantic analysis, not a transformer embedding, and the difference matters enough to say out loud. LSA takes the term–document matrix, truncates its singular value decomposition to six dimensions, and lets terms that co-occur across the corpus collapse onto shared axes. That is genuinely semantic — it will connect two pieces that never use the same word — but the meaning it knows is only the meaning present in these twelve documents. A sentence embedding model brings meaning learned from far more text.

      The reason it is not a model is the interesting constraint. Embedding your query needs the same model that embedded the documents, which means a network call and a key. This site is static and asserts in its own test suite that no page reaches a third-party origin, so the whole comparison would have to become a lookup table of canned queries. That is the actual lesson underneath every RAG architecture diagram: retrieval is cheap arithmetic you can do anywhere, and the expensive, service-shaped part is turning text into a vector in the first place.
